危険な書き方（f文字列で直接埋め込む）


exercise = "ベンチプレス"
cur.execute(f"INSERT INTO kintores (exercise) VALUES ('{exercise}')")
これはexerciseの中身をそのまま文字列に埋め込んで、最終的にこういうSQL文を作ります。


INSERT INTO kintores (exercise) VALUES ('ベンチプレス')
普通の値ならこれで問題なく動きます。でも、もしexerciseの中に悪意のある文字列が入っていたらどうなるでしょうか。例えば誰かがDiscordで種目名としてこう送ってきたとします。


exercise = "x'); DROP TABLE kintores; --"
f文字列で組み立てると、SQL文はこうなってしまいます。


INSERT INTO kintores (exercise) VALUES ('x'); DROP TABLE kintores; --')
これは「INSERT文を1つ実行」ではなく、「INSERT文の後にセミコロンで区切られた別のSQL文（テーブル削除）」として解釈されてしまう可能性があります。ユーザーが入力した文字列が、データではなく「SQLのコマンドの一部」として実行されてしまう。これがSQLインジェクションです。

安全な書き方（?プレースホルダー）


exercise = "x'); DROP TABLE kintores; --"
cur.execute("INSERT INTO kintores (exercise) VALUES (?)", (exercise,))
この場合、SQLiteのライブラリがexerciseの中身を**「純粋な1つの値（データ）」として扱う**ことを保証してくれます。中に'や;のような特殊文字が入っていても、SQL文の構造そのものには一切影響しません。「これは値であって、コマンドの一部ではない」とライブラリレベルで区別されるイメージです。

つまり、

f文字列 → 「SQL文の文字列」に値を混ぜて組み立てる（危険）
?プレースホルダー → 「SQL文の構造」と「値」を別々に渡す（安全）
という違いです。今回のBotはDiscordで誰でもメッセージを送れるので、種目名などにどんな文字列が来るか分かりません。だからこそプレースホルダーを使う習慣が大事です。

もっと分解して説明します。

SQLでは、セミコロン;は「1つの文が終わって、次の文が始まる」という意味の区切り文字です。人間で言う「。（句点）」だと思ってください。

さっきの完成したSQL文をもう一度見てみます。


INSERT INTO kintores (exercise) VALUES ('x'); DROP TABLE kintores; --')
これを;で区切って、3つの塊に分けてみます。


① INSERT INTO kintores (exercise) VALUES ('x')
② DROP TABLE kintores
③ --')
SQLを実行するプログラムは、これを「文が3つ並んでいる」と読みます。

①「exercise列に'x'という値を1件追加してね」→ 普通のINSERT文
②「kintoresテーブルを削除してね」→ これが混入した攻撃
③--はSQLの「コメント（ここから後は無視）」という意味の記号なので、余った')はコメントとして無視され、エラーにならず綺麗に終わる

つまり、exerciseという1つの変数の中身のはずだったものが、f文字列で組み立てたことで「INSERT文を終わらせて、勝手に新しいDROP TABLE文を開始する」という別のコマンドとして実行されてしまった、ということです。

本来exerciseは「データ（値）」であるべきなのに、f文字列で直接文字列を組み立てると、SQLを実行する側からは「データ」と「SQLのコマンド」の区別がつかなくなります。ユーザーが送ってきた文字列の中に'や;が混ざっていると、それがSQL文の構造を書き換える力を持ってしまうわけです。

?プレースホルダーを使うと、SQLiteのライブラリが「これはVALUESに入る1個のデータだよ」と最初から決めた状態で値を渡すので、中に;や'が入っていても、それはただの「変な文字列データ」として扱われるだけで、SQL文の構造自体は変わりません。
